# gacha-stockout-simulator（ガチャ枯渇予測シミュレーター）

人気ガチャの **枯渇スピード** をシミュレーションして、
**「いつ・どこに行けばまだ残っている確率が高いか」** を可視化するツールです。

## 背景 / 解決したいこと
人気ガチャは「発売日でもう無い」「店によって残り方が違う」など不確実性が高く、
来店タイミングや店舗選びが“感覚”に寄りがちです。
本プロジェクトは **購入者行動モデル × 在庫推移** を用いて、
来店判断を **根拠ベース** にすることを目的とします。

## 体験（ユーザーストーリー）
1. ガチャの条件（人気度・発売日/発売時間・店舗タイプなど）を入力
2. 購入者の来店タイミングと回数をモデル化してシミュレーション
3. 在庫推移と枯渇予測を出力
4. 「この条件なら発売日午前が有利」など行動提案を表示

## できること（MVP）
- ガチャ条件の入力（人気度 / 発売日・発売時間 / 店舗タイプ など）
- 購入者行動モデルのシミュレーション
  - 来店タイミング分布
  - 回す回数（1回〜複数回）
- 出力
  - 売り切れ予測時刻（例：初日 14:30頃）
  - 時間帯別「残っている確率」
  - 在庫推移グラフ
- 行動提案
  - 例：「発売日午前中に行くべき」「この店舗は初日夕方以降は厳しい」

## 余力（やりたい）
- SNS拡散 ON/OFF で枯渇スピード比較
- 条件保存・再シミュレーション
- 店舗混雑/移動時間も加味した「おすすめ来店プラン」

---

## モデル概要（ざっくり）
- **需要側（購入者）**
  - 来店タイミング：分布（例：発売直後ピーク、昼休みピーク、夕方ピーク）
  - 購入回数：1回〜複数回（分布）
  - SNS拡散：需要増加の係数として扱う（ON/OFF）
- **供給側（在庫）**
  - 初期在庫：店舗タイプにより差（例：大型店 > 駅ナカ > 小型店）
  - 補充：基本なし（必要なら後で拡張）

## AWSデプロイ手順（できるだけ無料）
無料枠（新Free Tierのクレジット制）を最大限使う前提の「EC2 1台でフロント＋バックをまとめて運用」構成の例です。
学習目的でEC2を使い、コストは停止運用と小サイズで抑える想定です。

### 1. AWSアカウント作成と無料枠確認
- AWS無料枠（12か月のFree Tier）を確認
- 請求アラート（AWS Budgets）を作成

### 2. EC2インスタンス作成
1. EC2で小さめのインスタンスを作成（例: `t3.micro`）
2. セキュリティグループで `80/443` を開放
3. SSHでログインできるように設定

### 3. バック（Spring Boot）をEC2で起動
1. `backend` をビルド  
   - `./gradlew bootJar`（または `mvn package`）
2. EC2にアプリを配置
3. `java -jar` で起動
4. `http://<EC2のIP>:8080` でAPI疎通確認

### 4. フロント（React）をEC2で配信
1. `frontend` をビルド  
   - `npm run build`
2. Nginxをインストールして静的配信
3. `/` は `frontend/dist` を配信
4. `/api` はSpring Bootへリバースプロキシ（Nginx設定）

### 5. 本番動作の確認
- ブラウザでEC2のIPへアクセスし、画面が出るか確認
- フロントからAPIを叩いて結果が返るか確認

### 無料枠での注意点
- 新Free Tierはクレジット制（6か月 or 上限消費まで）
- EC2は常時起動でクレジット消費が早いので、使わない時は停止
- ログ（CloudWatch）やEBSの容量も課金対象になるため注意
